### 回流
我们对DOM的修改引发了DOM的几何属性的变化（大小，宽高，位置或者显示隐藏仅指display:none），浏览器需要重新计算元素的几何属性，再将计算后的结果绘制出来，这个就是浏览器的回流，也叫重排。

### 重绘
我们队DOM的修改不引发DOM的几何属性变化，如背景色，颜色等，浏览器不需要重新计算元素的几何属性而直接为元素绘制上新的样式，这个过程就是重绘。

### 哪些实际操作会导致回流与重绘
只要不触发回流，但是又改变了DOM的样式的修改都会造成重绘，这个比较好理解。

#### 可能触发回流的操作
- 最耗费性能，改变DOM的几何属性  
常见的几何属性：padding,margin,border,width,height,left,top,bottom,right，其实理解上去很容易的，改变元素大小，位置等相关属性的都是几何属性。这样的操作都会引起相关的节点（父子节点，兄弟节点）都需要重新计算。

- 比较耗费性能的，改变DOM结构  
这里主要指的是节点的增减、移动等操作。浏览器引擎布局的过程，顺序上可以类比于树的前序遍历——它是一个从上到下、从左到右的过程。通常在这个过程中，当前元素不会再影响其前面已经遍历过的元素。

- 易忽略的操作  
当你要用到像这样的属性：offsetTop、offsetLeft、 offsetWidth、offsetHeight、scrollTop、scrollLeft、scrollWidth、scrollHeight、clientTop、clientLeft、clientWidth、clientHeight 时，你就要注意了！  
这些属性都是即时属性，需要浏览器去实时计算的，每一次计算都是一次回流。当我们调用了 getComputedStyle 方法，或者 IE 里的 currentStyle 时，也会触发回流。原理是一样的，都为求一个“即时性”和“准确性”。

### 规避回流与重绘

- 尽量利用JS计算来替代频繁render
```js
  // this is bad 
  // 获取el元素
  const el = document.getElementById('el')
  // 这里循环判定比较简单，实际中或许会拓展出比较复杂的判定需求
  for(let i=0;i<10;i++) {
      el.style.top  = el.offsetTop  + 10 + "px";
      el.style.left = el.offsetLeft + 10 + "px";
  }
```
```js
  // this is good 
  // 获取el元素
  const el = document.getElementById('el')
  const offsetTop = el.offsetTop
  const offsetLeft = el.offsetLeft
  // 这里循环判定比较简单，实际中或许会拓展出比较复杂的判定需求
  for(let i=0;i<10;i++) {
      offsetTop  = offsetTop  + 10;
      offsetLeft = offsetLeft + 10;
  }
  el.style.offsetTop = offsetTop + "px";
  el.style.offsetLeft = offsetLeft + "px";
```

- 避免逐条改变样式，用类名去合并样式  
```js
// this is bad
const container = document.getElementById('container')
container.style.width = '100px'
container.style.height = '200px'
container.style.border = '10px solid red'
container.style.color = 'red'
```

```html
<!-- this is good -->
<html>
  <head>
    <style>
      .basic_style {
        width: 100px;
        height: 200px;
        border: 10px solid red;
        color: red;
      }
    </style>
  </head>
  <body>
    <div id="container"></div>
    <script>
      const container = document.getElementById('container')
      container.classList.add('basic_style')
    </script>
  </body>
</html>
```

- 将DOM'离线'
上述所说的回流和重绘，都是基于元素在文档流中。一旦我们将整个元素设置为display: none，那么后续对于整个元素的操作都不会触发回流和重绘，这就四所谓的将DOM‘离线’。  
```js
// this is bad
const container = document.getElementById('container')
container.style.width = '100px'
container.style.height = '200px'
container.style.border = '10px solid red'
container.style.color = 'red'
...（省略了许多类似的后续操作）
```
```js
// this is good
const container = document.getElementById('container')
container.style.display = 'none'
container.style.width = '100px'
container.style.height = '200px'
container.style.border = '10px solid red'
container.style.color = 'red'
...（省略了许多类似的后续操作）
container.style.display = 'block'
```
上述的办法依然会造成昂贵的回流，但是相比较于源代码的频繁操作，这里隐藏和显示还是值得的。


### Flush队列：浏览器的自带优化
```js
let container = document.getElementById('container')
container.style.width = '100px'
container.style.height = '200px'
container.style.border = '10px solid red'
container.style.color = 'red'
```
如果我们按照上面的知识，上面这段代码会造成三次回流和一次重绘，但是事实上只会有一次回流和重绘。因为浏览器是聪明的，知道每一次回流会消耗巨大的性能，于是它自己缓存了一个 flush 队列，把我们触发的回流与重绘任务都塞进去，待到队列里的任务多起来、或者达到了一定的时间间隔，或者“不得已”的时候，再将这些任务一口气出队。因此我们看到，上面就算我们进行了 4 次 DOM 更改，也只触发了一次 Layout 和一次 Paint。  
大家这里尤其小心这个“不得已”的时候，上文提到过有一类属性很特别，它们有很强的“即时性”。当我们访问这些属性时，浏览器会为了获得此时此刻的、最准确的属性值，而提前将 flush 队列的任务出队——这就是所谓的“不得已”时刻。

### 小结
并不是所有浏览器都是一致的表现，所以不能依赖浏览器本身去做这些优化，我们依然要去手动优化。
