### 浏览器核心
JS引擎 和 渲染引擎

### 渲染原理
- 构建DOM：解析 HTML 以创建的是 DOM 树（DOM tree ）：渲染引擎开始解析 HTML 文档，转换树中的标签到 DOM 节点，它被称为“内容树”。（ 字节数据 => 字符串 => Token => Node => DOM ）
- 构建CSSOM：解析 CSS（包括外部 CSS 文件和样式元素）创建的是 CSSOM 树。CSSOM 的解析过程与 DOM 的解析过程是并行的。（ 字节数据 => 字符串 => Token => Node => CSSOM ）
- 构建渲染树：CSSOM 与 DOM 结合，之后我们得到的就是渲染树（Render tree ）
- 布局（也称回流）：从根节点递归调用，计算每一个元素的大小、位置等，给每个节点所应该出现在屏幕上的精确坐标，我们便得到了基于渲染树的布局渲染树（Layout of the render tree）。
- 绘制：GPU绘制，合成图层，显示到屏幕上

### CSS的阻塞
1、CSS 不会阻塞 DOM 的解析，但是会阻塞 DOM 的渲染。  
2、存在阻塞的CSS资源时，浏览器会暂停执行JS，直至CSSOM下载构建完成。  


### JS的阻塞  
1、JS对DOM的阻塞  
JavaScript的加载、解析与执行会阻塞DOM的构建，也就是说，在构建DOM时，HTML解析器若遇到了JavaScript，那么它会暂停构建DOM，将控制权移交给JavaScript引擎，等JavaScript引擎运行完毕，浏览器再从中断的地方恢复DOM构建。

2、JS对CSSOM的阻塞  
因为js想操作CSSOM，那么必须有完整的CSSOM，如果这时CSSOM的构建还没完成，那浏览器会阻塞js优先完成CSSOM的构建。
自认为JS不会阻塞CSSOM，但是 掘金小册前端性能优化与实践中修言表示JS的执行会阻止CSSOM，需要思考🤔。
