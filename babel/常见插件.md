
babel-polyfill babel-runtime 以及babel-plugin-transform-runtime的区别与联系

babel默认只会转化语法，但是不会转化API，所以我们想使用新的API就需要其他操作。


babel-polyfill直接修改浏览器环境下的全局变量，污染了全局变量，而且babel-polyfill的包比较大，打包的时候会导致重复打包
```js
'use strict';
function _defineProperty(obj, key, value) {
  if (key in obj) {
    Object.defineProperty(obj, key, {
      value: value,
      enumerable: true,
      configurable: true,
      writable: true
    });
  } else {
    obj[key] = value;
  }
  return obj;
}
var obj = _defineProperty({}, 'name', 'JavaScript');
```



babel-runtime允许我们按需加载, 像下面这样使用

```js
var _extends = require("babel-runtime/helpers/extends");

_extends({}, {});
```



但是babel-runtime的写法还是比价麻烦，需要的模块里都需要主动去引入使用的模块，所以这时候就需要babel-plugin-transform-runtime。它会分析我们的 ast 中，是否有引用 babel-runtime 中的垫片（通过映射关系），如果有，就会在当前模块顶部插入我们需要的垫片。

这样我们就既不用在每个模块里面重复的引用，又可以完美的使用新的API，但是 babel-runtime 存在的问题就是不模拟实例，也就是说内置对象原型上的方法通过babel-runtime无法使用的，只能通过babel-polyfill。这样就又回到第一个问题了，怎么办？


### 目前最终的解决方案就是babel-preset-env

babel-preset-env 能根据当前的运行环境，自动确定你需要的 plugins 和 polyfills。通过各个 es标准 feature 在不同浏览器以及 node 版本的支持情况，再去维护一个 feature 跟 plugins 之间的映射关系，最终确定需要的 plugins。关于详细的配置说明，请点击这里
